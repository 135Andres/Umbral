## GOAL

`UD-016` fixes the performance objective: reduce content reading and hashing during
re-observation to O(changes), without claiming O(changes) for filesystem traversal.
`UD-021` bounds verdict preservation by the evidence each observation actually holds.
`UD-023` adds the historical guarantees that any implementation must preserve.

The version must therefore avoid unnecessary content reads without turning metadata into content
evidence, losing material acquisition history, or silently rewriting historical emissions.

## DECIDED BOUNDARIES

- Content-read/hash work is the only O(changes) objective; traversal remains O(corpus)
  (`UD-016`).
- A skipped content read is never reported as content verification (`UD-017`).
- `ctime` is only a heuristic and cannot establish content equality (`UD-018`); it is a term of
  the skip condition (`UD-035`).
- `basis` applicability and provenance must be determinable; their mechanisms remain open
  (`UD-019`, `UD-020`).
- Fresh reads, reused evidence and UNKNOWN/error remain distinguishable; verdict equivalence is
  bounded by the evidence actually held (`UD-021`).
- The output uses the grammar family and contract-versioning direction selected by `UD-022`;
  exact representations remain open.
- Historical emission, observational scope and coverage, material acquisition history and later
  re-evaluation obey `UD-023`.

## KNOWN LIMITATIONS (slice 3)

- **L1 — inode reuse with matching metadata.** Demonstrated on ext4 (1000/1000 attempts,
  `experiments/e-td-2-3/` §5.2) for a metadata-only condition; with `ctime` in the condition no
  case was skipped. Not provoked on tmpfs or btrfs.
- **`ctime`'s residual false negative** (F-TD-4, `UD-021`). A change leaving identity, size,
  mtime and `ctime` equal is skipped, and the carried reading makes the verdict `unchanged` —
  shown on hand-built input (`tests/skip.rs`,
  `the_residual_false_negative_is_real_on_hand_built_input`). Reachable on filesystems that do
  not generate their own timestamps and within one coarse clock tick (§D.4); not provoked by
  E-TD-2 (0 of 150) or E-TD-3.
- **Metadata-only changes cost a read** (`chmod`, `chown`, a new hard link), accepted by `UD-018`.
- **A rename is read**: the skip compares a path only with its own previous observation
  (`UD-036`). Still O(changes): a rename is a change.

## CROSS-CUTTING CRITERIA

- **A2-V8 — emissions are not rewritten.** `umbral/tests/traversal.rs`
  (`no_later_step_rewrites_an_earlier_emission`) stores every value of every run after each step
  of a sequence that starts from a `umbral-v0.1` log and observes a changing tree, and shows that
  no later step changes an earlier value. The only values a migration adds to earlier rows are
  `content_error=not-recorded` (`UD-029`), the traversal class `not-recorded` (`UD-037`), and
  `hash_read_run = run_id` — **the owner's explicit exception in `UD-036`**: a value derived with
  certainty from the schema version (those builds read every file in its own run), chosen knowing
  that A2-V8's text admits only "not recorded" values. Output is a view and is not stored, so no
  emission of a run can be rewritten by a later one.
- **A2-V9 — multiplicity is not assumed.** Reviewed on 2026-10-03: `umbral/src`, `umbral/tests`,
  `umbral/README.md`, `umbral/CONTRACT.md`, `README.md` and this record, searched for
  `dedup`, `multiplicit`, `exactly once`, `twice`, `duplicate`. Found: "accounted for exactly once"
  (each path receives one verdict — a classification property), "must appear exactly once" (a
  count is printed once per output — a format property), "duplicate content is not identity",
  and the primary key `(run_id, path)` (one observation per path per run — observation identity,
  `UD-026`). None asserts that repeated identical emissions are preserved, or that their loss is
  permitted. P5 stays INDETERMINATE and outside the contract.
