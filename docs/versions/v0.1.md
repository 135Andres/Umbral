## GOAL

> A person can point Umbral at a directory they own, record what is there, and later read back
> what is known, when it was known, and what changed.

## USER-VISIBLE OUTCOME

Before v0.1, there was nothing a person could run: the only code in the repository was the
frozen V0 experiment, whose CLI printed counts and had no reader-facing surface at all — the
gap V0 recorded as SC-5 and closed itself at PARTIAL for.

After v0.1: the person runs one observation over a real directory and gets a report that says
which entries are known, which are verified by content and which are not, when the last
observation happened and whether it was complete, what changed since the previous one and on
what evidence, and what is ambiguous and why — with every line labelled `observed`,
`derived`, `ambiguous` or `unknown`.

## CAPABILITIES

1. A workspace concept: an observed root plus its local record, remembered between runs.
2. The observation core, re-derived as new code: deterministic scan, physical identity
   evidence, guarded content observation, pure reconciliation, append-only persistence.
3. A read-only text surface: current state, changes between the last two runs, and one path's
   history.
4. An explicit separation, in the output, between observed / derived / ambiguous / unknown.
5. Errors and unobservable paths represented in the output, never omitted.

## DEPENDENCIES

None that did not already exist. No capability of a later version is used, and none is
implied. The version depends on no decision that is still open: not Q25 (persistence model),
not Q2/Q5 (what is genuinely non-derivable), not multi-writer concurrency, not watcher, not
API, not UI.

## NON-GOALS

Search beyond listing; watcher; daemon; events; FTS; embeddings; API; UI; MCP; AI in any
form; sync; multi-device; multi-writer; permissions; semantic layer; Project Reality;
versioning; exporting to any format; modifying `fsp-check/`; closing Q25, Q2, Q5, Q1, Q15,
0.7 or 0.8; selecting any architecture.

## TESTING

- **89 tests** when this record was written, in nine integration suites plus the library and
  binary unit tests; 101 at the 2026-10-02 audit, and 114 after its corrections
  (`D-V01-6` … `D-V01-12`), now including two unit tests in `src/content.rs`. The later
  corrections `D-V01-13` … `D-V01-16` (`UD-032`) were made on the v0.2 branch, whose suite
  then counted 134.
- **Property testing** over reconciliation: every path on both sides accounted for exactly
  once; renames always carry matching physical evidence.
- **A falsification harness** with an independent model of the tree that separates *objects*
  from *paths*, so hard-link aliasing is modelled correctly. It never calls `reconcile` and
  never uses the tool's types to decide what is true; it is compared against them.
- **Directory deletion is generated from the start**, with an assertion that the generator
  covers every operation kind. The frozen V0 harness never generated it, which is how finding
  F-5 happened; that obligation is carried forward explicitly.
- **Generator preconditions are explicit** — an operation whose precondition does not hold is
  skipped, never applied to inflate coverage.

## KNOWN LIMITATIONS

Stated because they are known, not because they are acceptable:

1. **O(corpus) per run.** v0.1 re-observes the whole tree on every `observe`. Measured and
   stated; not optimised, and not a defect against this version's contract.
2. **One writer.** Single process, single logical writer. Multi-writer concurrency is
   untouched and remains an open question of the project.
3. **No durability claim.** Process-kill and power-loss durability are outside v0.1's
   contract. SQLite's defaults are used; nothing is tuned.
4. **Scan-based only.** No event-driven change detection.
5. **One filesystem family observed.** tmpfs, btrfs and ext4. Behaviour on other families is
   untested.
6. **A `stat` guard has a documented blind spot.** A rewrite that restores both size and exact
   mtime inside the read window is invisible to it. Comparing content hashes across
   observations is the partial backstop. Asserted in
   `tests/content_observation.rs::a_stat_guard_cannot_see_a_rewrite_that_restores_size_and_mtime`.
7. **A moved root becomes a different workspace** with an empty history. A deliberate
   consequence of writing nothing into the user's tree.
8. **F-V01-1 (finding).** `status` reports content verification as counts. To identify *which*
   entries are verified requires one `show` per path; there is no listing command. The reader
   protocol's question is answerable but not efficiently. Accepted for v0.1 — adding a listing
   command after the acceptance criteria were fixed would be scope growth — and handed to a
   later version.
9. **Inode reuse is designed for but was not observed** on tmpfs or btrfs. The classification
   that handles it is asserted deterministically against hand-built observation sets; the
   filesystem's actual behaviour is recorded, never required.
10. **The tool states its limits only reactively.** It never affirmatively says what it does not
    know or refuses to assert, so on a fully-observed tree a reader cannot name either. Found by
    the reader protocol; see F-V01-3. **Deliberately not fixed**: an affirmative statement of
    limits is outside v0.1's contract. The protocol was amended instead, so that the fixture
    exercises the limit categories.
11. **A1 is not satisfied.** Two runs have been executed. The first, by the project owner, did not
    answer Q6–Q8. The second, by an isolated-context agent, answered all eight, but is registered
    as **EVIDENCIA-B** rather than as A1 because it is an agent, not an independent human reader,
    and it does not repair the first run's D4 weakness. **An independent human reader remains
    outstanding.**
12. **Four legibility debts are carried deliberately.** `unchanged` states neither its basis nor
    its scope and can appear beside observations that seem to contradict it (F-V01-6); a rename's
    justification is invisible, so a justified match cannot be told from a lucky guess (F-V01-7);
    where an observed and a derived value coincide the labels alone do not let the rule be
    reconstructed (F-V01-8); and the output's vocabulary is defined nowhere in the output
    (F-V01-9). The owner declined to change behaviour for these, so **the contract is not
    narrowed silently** — each is named here as debt. F-V01-8 and F-V01-9 join the deferred half
    of F-V01-3 as one open question for after v0.1: how much explanation the output should carry.
    See `experiments/v0.1-reader-protocol/EVIDENCE-B.md` §10.

Corrected during the version, and no longer a limitation: values the tool computes were labelled
`observed` (F-V01-2). See the findings table.
