# v0.2 historical contract — identifier definitions (extract)

Status: **RESEARCH ARTIFACT (DT5) — extract. Not authority.** Created 2026-10-02 (audit
2026-10-02, F3).

## Why this file exists

Decision records `UD-023`–`UD-027` and the P5 interpretive record in
[`docs/decisions/DECISIONS.md`](../docs/decisions/DECISIONS.md) cite identifiers whose
definitions lived only in agent working reports (2026-09-13 cycle, "derivation of the minimal
historical core"). Those reports are part of the owner's private record and are not published.
A public record must not depend on a definition a public reader cannot see, so this file
publishes **only the definitions** — one line each — and nothing of the analysis behind them.

What this file is NOT:

- not a restatement of the decisions — the decision records are the authority; where a line
  here and a record disagree, the record wins and this file is wrong;
- not the analysis — the arguments, adversarial passes and rejected alternatives stay private;
- not a selection of anything listed below as a candidate.

Definitions are translated from the working reports, which were written in Spanish.

## 2. `N1`–`N10` — the candidate minimal core (analysis, not adopted)

Ten conceptual distinctions derived from D1–D5 as a candidate "minimal historical core". Each
names something that must remain recoverable; none is a field, an object or a schema.

| Id | Distinction |
|---|---|
| N1 | the historical act of emission — which result Umbral produced, in which act, under which contract meaning |
| N2 | strata of evaluation — historical code behaviour vs intended rules vs later evaluator/rules |
| N3 | comparative anchoring — the subject of a claim and the observations or runs used as reference and as compared state |
| N4 | effective historical scope — what was included or excluded, with the contemporary reason and its partiality |
| N5 | achieved coverage and limitations — what part of the scope was sufficiently observed on each side, and where the gaps were |
| N6 | material observational support — the observational facts that were available: values, absence of value, epistemic state, limitations |
| N7 | acquisition history — per material component: fresh acquisition, reuse, failed attempt, known non-attempt, unknown whether attempted |
| N8 | association between emission and support — which support backed or conditioned the emission, in which role |
| N9 | temporality of information and explanation — known during the run vs acquired or inferred afterwards |
| N10 | re-evaluation state and context — a re-evaluation kept apart from the emission, with its support, timing, rules, evaluator and outcome |

**The reduction the decision records cite.** An adversarial minimality analysis reduced the
ten to five distinctions, one transversal one (contemporaneity / temporal provenance) and one
derivable one (coverage). Two absorptions were conditional, and the conditions were closed by
decisions:

- **N3 → N8** (comparative anchoring absorbed into the typed association) holds only if the
  association can identify comparison sides — closed by `UD-024` (D6).
- **N5 → derivable** (achieved coverage derived rather than a core distinction) holds only if
  acquisition is recorded per component together with traversal facts — closed by `UD-025` (D7).

`UD-023` states that the exact reduced set "remains analysis until separately accepted". That
remains true: nothing in this section is adopted.

**Do not confuse.** The private working reports also use `N` for two unrelated lists (a six-level
model of observation policy, and eight test cases). Neither is cited by any public record, and
neither is published.

## 3. `M6` — a candidate evidence-representation model (not selected)

The technical design defines M1–M5 ([`V0.2-TECHNICAL-DESIGN.md`](../docs/candidates/V0.2-TECHNICAL-DESIGN.md)).
A later working report proposed a sixth:

> **M6** — every result carries its evidence flags with explicit values (for example
> `content-changed=none|false|true`, `object-survives=…`, `reason=…`, `scan-complete=…`), and the
> contract defines, for each combination of result kind and flag values, which observed fields
> form the result's basis. No predicate name is invented: the flags are the discriminator.

Status in the working reports: *insufficiently demonstrated* as a key of the form
`(kind, flags)`. `UD-023` and `docs/versions/v0.2.md` name M6 only to say it is not selected.
